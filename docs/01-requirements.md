# Student Management — Requirements

## เป้าหมาย

สร้างเว็บจัดการข้อมูลนักเรียนแบบ CRUD สำหรับแบบทดสอบสมัครตำแหน่งโปรแกรมเมอร์ โดยใช้ Next.js, NestJS, Prisma ORM และ PostgreSQL ตามการยืนยันของผู้สมัคร

ข้อมูลจากประกาศรับสมัครใช้เป็นบริบทในการเลือกเทคโนโลยีเท่านั้น ข้อกำหนดของระบบยึดตามโจทย์ CRUD และการตัดสินใจด้านสถาปัตยกรรมที่ระบุในเอกสารชุดนี้

## ขอบเขต

ระบบต้องรองรับ:

1. แสดงรายการนักเรียน
2. เพิ่มนักเรียน
3. เปิดดูข้อมูลนักเรียนหนึ่งรายการผ่าน API
4. แก้ไขนักเรียน
5. ลบนักเรียนหลังผู้ใช้ยืนยัน
6. ค้นหาจากชื่อ นามสกุล หรือชื่อเล่น
7. แบ่งหน้าและเรียงลำดับรายการ
8. แสดงสถานะกำลังโหลด สำเร็จ ไม่พบข้อมูล และผิดพลาด

ไม่รวมระบบเข้าสู่ระบบ สิทธิ์ผู้ใช้ รูปประจำตัว ห้องเรียน คะแนน และการนำเข้าหรือส่งออกข้อมูล

## ข้อมูลนักเรียน

| Field       | ความหมาย        | กฎ                                                           |
| ----------- | --------------- | ------------------------------------------------------------ |
| `id`        | รหัสภายใน       | UUID v4 สร้างโดยฐานข้อมูล                                    |
| `firstName` | ชื่อ            | บังคับ, Unicode, หลัง trim ต้องไม่ว่าง, ไม่เกิน 100 ตัวอักษร |
| `lastName`  | นามสกุล         | บังคับ, Unicode, หลัง trim ต้องไม่ว่าง, ไม่เกิน 100 ตัวอักษร |
| `nickname`  | ชื่อเล่น        | บังคับ, Unicode, หลัง trim ต้องไม่ว่าง, ไม่เกิน 50 ตัวอักษร  |
| `birthDate` | วันเกิด         | รูปแบบ `YYYY-MM-DD`, เป็นวันที่จริง, ไม่เกินวันปัจจุบัน      |
| `createdAt` | เวลาสร้าง       | UTC ISO 8601, server เป็นผู้กำหนด                            |
| `updatedAt` | เวลาแก้ไขล่าสุด | UTC ISO 8601, server เป็นผู้กำหนด                            |

ชื่อและชื่อเล่นซ้ำกันได้ อายุไม่ถูกเก็บในฐานข้อมูลเพราะเป็นข้อมูลที่คำนวณจากวันเกิดได้

## Acceptance criteria

### Create

- ข้อมูลถูกต้องตอบ `201` และคืน student contract ครบ
- trim ช่องว่างรอบชื่อก่อนบันทึก
- validation ไม่ผ่านตอบ `400` และต้องไม่สร้างข้อมูล
- field ที่ไม่อยู่ใน contract ต้องถูกปฏิเสธ
- refresh หน้าเว็บต้องไม่สร้างข้อมูลซ้ำ

### Read

- รายการว่างตอบ data ว่างพร้อม pagination metadata ที่คงรูปแบบเดิม
- ค้นหาแบบ case-insensitive จากสามช่องชื่อ
- pagination ต้องคืน `total` ก่อนแบ่งหน้าและคำนวณ `totalPages` ถูกต้อง
- UUID ผิดรูปแบบตอบ `400`; UUID ถูกต้องแต่ไม่มีข้อมูลตอบ `404`

### Update

- ใช้ `PATCH` และแก้เฉพาะ field ที่ส่งมา
- trim string และตรวจ birth date ด้วยกฎเดียวกับ create
- body ว่างหรือมีเฉพาะ field ที่ไม่รู้จักตอบ `400`
- ไม่พบข้อมูลตอบ `404`

### Delete

- หน้าเว็บต้องถามยืนยันและระบุชื่อนักเรียนก่อนลบ
- ยกเลิกแล้วต้องไม่เรียก delete API
- ลบสำเร็จตอบ `204` โดยไม่มี response body
- ไม่พบข้อมูลตอบ `404`

### UX และ accessibility

- ทุก input เชื่อมกับ label
- error ใช้ element ที่ assistive technology รับรู้ได้
- loading และ success status ต้องอ่านได้โดย screen reader
- ปุ่มแก้ไขและลบต้องมี accessible name ที่ระบุชื่อนักเรียน
- ตารางต้องไม่ render เมื่อไม่มีข้อมูล และต้องมี empty state ที่ชัดเจน

## Definition of Done

- test ตาม `docs/04-test-plan.md` ผ่านทั้งหมด
- Prisma migration ใช้กับ PostgreSQL test database ได้จากฐานข้อมูลว่าง
- backend typecheck, lint, unit, integration, e2e และ build ผ่าน
- frontend typecheck, lint, component, Playwright และ build ผ่าน
- production URL ใช้ CRUD ได้ครบโดยไม่เปิด debug information
- repository ไม่มี secret และไม่มี `.env` ถูก commit
